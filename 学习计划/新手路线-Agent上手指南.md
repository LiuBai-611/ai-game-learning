## 0. 先立规矩：我的角色（这段最关键，请先看）

**我只做四件事**：

| 我做 | 具体是什么意思 |
|---|---|
| **给选项** | 一件事给你 2～3 条路，说清各自的代价（花多少时间、有多大风险、要不要装东西） |
| **解释现象** | 你用生活话问，我用生活话答；你说"听不懂"，我就换一种说法，不重复原话 |
| **挑错** | 你做完了我指出问题——**顺序永远是"你先做，我再挑"，不是"我做好你来看"** |
| **收拾环境** | 装软件、修路径、通网络这类"学不到东西但很卡人"的事，我包了 |

**我不做**：
- 不替你完成学习任务（不替你填记录、不替你跑练习、不替你打卡）
- 不替你决定学什么、不主动改你的文件
- 不一次给你一大篇（超过一屏的内容，我拆成几步给）

> ⚠️ 如果你发现我又在"替你推进学习进度"，**直接说"越界了"**，我立刻停。
> （前面 Day 01～03 我就犯了这个问题：装 VS Code、跑三道题、填对比表，全是我做的，那些本该是你做的。）

## 1. Agent 是什么（30 秒版）

|  | 普通聊天 AI | **Agent（智能体）** |
|---|---|---|
| 能做什么 | 只会"说话"：你问它答 | **能动手**：读文件、改文件、跑命令、联网、调用别的工具 |
| 你给它什么 | 一段话 | 一个**目标** + 它能用的工具 + 一条底线（哪些事不许做） |
| 失败时 | 答得不好，你重问 | **可能真把你的文件改坏** → 所以要验收 |

**一句话**：Agent = 模型 + 一双手 + 一盒工具 + 一套规矩。
你现在正在用的 DeepSeek Harness（DSH）就是一个 agent 工作台；WorkBuddy、豆包也各自带着 agent 能力。

**"agent 的编程语言"没有你想的那么神秘**：它不是一门新语言，而是三样普通东西的组合——
1. **提示词**（用人话写的指令，通常存在 md 文件里，比如你项目里的 `AGENTS.md`）
2. **配置**（JSON / YAML，告诉工具"怎么运行、能碰哪些目录"）
3. **一点点普通脚本**（JavaScript 或 Python，用来把重复动作写死）

你不需要会写整套程序，**只需要看得懂 + 会改一个地方**。这就是第 4 节的全部内容。

## 2. 怎么用我：4 步循环

```
① 你：一句话说清"我想要的结果"        （不用技术词，说结果不说做法）
② 我：给 2～3 个方案 + 各自的代价     （你说选哪个）
③ 你：自己动手，我逐步给指令           （卡住就把报错原文贴给我）
④ 我：验收 + 告诉你哪做对了、哪是运气  （再决定要不要记下来）
```

**规矩**：
- 每一步你都可以叫停或换方向
- 我给的步骤超过 7 步，就说明这件事该拆成两件做
- 一次只动一个地方，动完立刻看结果（这是学得最快的方式）

## 3. 项目菜单（挑着做，不按顺序）

每个项目都是一个**能拿在手上的东西**，不是"学一个概念"。
`⏱` 是大概时长（第一次做会比预估慢，正常）。

### A 档：会用（把 agent 当能干活的助手）

| # | 我想做的东西 | 拿到手的产出物 | 顺手会懂的知识 | ⏱ |
|---|---|---|---|---|
| A1 | 把一堆乱七八糟的文件按规则改名、分类到不同文件夹 | 一个整理干净的文件夹 | 「让 agent 先给方案再动手」 | 40 分 |
| A2 | 让 agent 读完一部长文档（或一堆截图），给我 5 条结论 | 一份摘要 | 「长文要分段喂、别一次塞」 | 30 分 |
| A3 | 把我最常重复的一句话，做成"一句话就能复用"的模板 | 提示词本里的 5 条模板 | 「好提示词的三个要件」 | 40 分 |
| A4 | 让两个 agent 干同一件事，比较谁的结果更靠谱 | 一篇 3 行结论的对比记录 | 「交叉验证」——**这是最省钱的质量手段** | 40 分 |

### B 档：会改（能读懂并小改 agent 的配置和指令）

| # | 我想做的东西 | 拿到手的产出物 | 顺手会懂的知识 | ⏱ |
|---|---|---|---|---|
| B1 | 找到 DSH 的一个配置文件，改一个设置并看到效果 | 一个被改过的配置 | JSON / YAML 长什么样 | 30 分 |
| B2 | 装一个别人写好的技能（skill），再把里面一句话改成我的规矩 | 一个被我改过的技能 | 技能 = 一份给 agent 的说明书 | 40 分 |
| B3 | 自己写一个最小技能（10 行字），让 agent 按我的规矩干活 | 一个属于我的 skill | 提示词怎么写才算清楚 | 40 分 |
| B4 | 给我的项目写一份 `AGENTS.md`，让 agent 每次都遵守 | 一个项目规矩文件 | 「项目记忆」是怎么起作用的 | 50 分 |

### C 档：会造（自己搭一个小工具）

| # | 我想做的东西 | 拿到手的产出物 | 顺手会懂的知识 | ⏱ |
|---|---|---|---|---|
| C1 | 写一个 10 行小脚本，自动做一件重复的事（统计/改名/备份） | 一个能双击运行的脚本 | 变量、函数、循环（读懂即可） | 60 分 |
| C2 | 让 agent 定时帮我汇总某个文件夹的变化 | 一份自动生成的日报 | 「触发器 + 输出」的思路 | 60 分 |
| C3 | 给 DSH 写一个小插件/面板 | 一个自己的面板或工具 | 插件机制、事件 | 2～3 小时 |

> **建议的走过顺序**：A1 → A4 → B1 → B2 → A3 → B3 → B4 → C1 → C2 → C3。
> 但这只是建议——**你想跳着做就跳**，兴趣比顺序重要。

## 4. 语言只学这些（够用即止，别买书）

**目标不是"会写程序"，是"看得懂 + 改得动 + 会看报错"。**

| 要懂的东西 | 一句话 | 你会在哪撞上它 |
|---|---|---|
| 变量 | 给一个值起个名字，如 `speed = 300` | 改参数（速度、数量、路径） |
| 字符串拼接 | 把两段文字接起来 | 报错信息、生成的文件名 |
| 条件判断 | `如果…就…` | "文件超过 10MB 就跳过" |
| 循环 | `对每一个…都做…` | 批量处理文件 |
| 函数 | 一段能反复用的动作，起个名字 | 看到 `xxx()` 就知道"这是一个动作" |
| JSON / YAML | 配置文件，只是"层级的清单" | 改设置、看插件配置 |
| 命令行 3 个动作 | `cd`（去哪个文件夹）、看目录、运行一个文件 | 装东西、跑脚本 |
| **读报错** | **从最后一行往前看**，最后一行才是真正原因 | 每次出错 |

> 🔑 **八条里最重要的一条是"读报错"**。学会它，前面七条大半可以边用边补。

**明确不学**：数据结构与算法、面向对象设计、编译原理、以及任何"先学完再做"的东西。

## 5. 三条纪律

1. **一次只改一个地方，改完立刻跑一次看变化。** —— 改动是最快的学法，"看教程"是最慢的。
2. **卡住 20 分钟就问我**（轻量版把原来的 40 分钟砍半）。死磕是放弃的前兆。
3. **每次结束留 3 行**：做了什么 / 搞懂了什么 / 下次从哪开始。
   写在你自己顺手的地方就行，**不用为了写日志专门建文件**。
