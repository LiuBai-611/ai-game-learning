# 多模型工具链配置手册（让 Codex / Claude Code 用别家的模型）

> **配合计划使用**：第 7 周 Day 42～47 学 Agent 与 API 时，先读本文件。
> **一句话结论**：能。但有两条路，成本和教育意义差很多，**你应该先走第一条，第二条只做实验**。
> ⚠️ 本文件涉及各家产品的配置方式和政策，**这些内容每一两个月就会变**。照着做之前，先看每节末尾的「官方核实链接」。

---

## 0. 先分清两种路线（这是最重要的一节）

| | **路线 A：直接配置各家自己的 API** | **路线 B：用聚合网关（Router / Gateway）** |
|---|---|---|
| 做法 | Codex 的配置文件里直接写 DeepSeek 的地址和 Key；Claude Code 的环境变量直接指向某家的地址 | 用一个中间服务（OpenRouter 之类，或你自己写的 Node 脚本）统一转发 |
| 你需要的账号 | 每家用哪家就注册哪家（DeepSeek / OpenAI / Anthropic / Google…） | 只注册一个聚合平台 |
| 配置量 | 每家配一次，工具里一个配置文件 | 配一次，换模型只改一个字符串 |
| 成本透明度 | 各家账单分开看，清楚 | 中间商有加价，看不清楚 |
| 安全风险 | 低（Key 只给官方） | **中～高：你的 Key 和全部代码都经过第三方服务器** |
| **学到的东西** | **多**：你会真正理解"API 是通用的，工具只是壳" | 少：你只是点了个开关 |
| 适不适合你现在 | ✅ **先用这个** | ⚠️ 等路线 A 玩明白了再用 |

**为什么建议先走路线 A**：你自己那份 12 周计划里，`Day 46～47` 本来就要用 Node.js 亲手写一次多模型调用。**走路线 A 你会顺便把这件事搞懂**；直接上网关，你只会得到"我配好了但不知道为什么能跑"。

**路线 B 的真正风险（必须知道）**：
1. 你的 API Key 和**项目全部代码**都要经过中间商的服务器
2. 中间商可能"偷换模型"（你付旗舰模型的钱，它转发给便宜模型，你从结果上很难发现）
3. 中间商可能随时涨价、限速、跑路
4. 有些中转服务**明确违反上游服务商的条款**，用它的账号可能被封
> 所以：**试验可以，长期依赖不行**。尤其是将来你要发布游戏、有商业代码的时候。

## 1. 一个必须搞懂的核心概念：接口协议才是关键

所有 AI 编程工具能换模型，靠的都是一个简单事实：

> **模型提供商的 API 是标准化的，工具只是"壳"。**

目前实际存在两套主流协议：

| 协议 | 谁定的 | 谁在用 |
|---|---|---|
| **OpenAI 兼容格式**（Chat Completions） | OpenAI，但已被行业广泛抄成事实标准 | 绝大多数家：OpenAI、DeepSeek、Google Gemini、xAI、Mistral、Groq、本地 Ollama……都提供"OpenAI 兼容端点" |
| **Anthropic 格式**（Messages API） | Anthropic | 原生 Claude，以及一些专门做"Anthropic 兼容层"的服务 |

于是有两个推论，理解它们你就理解了一切：

- **Codex 用 OpenAI 格式** → 任何提供"OpenAI 兼容端点"的模型都能塞进去（这就是 Codex 官方支持列一堆第三方的原因）
- **Claude Code 用 Anthropic 格式** → 想让它用别家模型，要么那家提供"Anthropic 兼容端点"，要么中间有个人帮你翻译格式

**"帮我翻译格式"这个中间人，就叫 gateway（网关）/ router（路由）/ relay（中转）**。理解了这句话，下面所有配置你都能自己推理出来。

## 2. 路线 A-1：让 Codex 用别家模型

Codex 的配置文件在 **`~/.codex/config.toml`**（Windows 上是 `C:\Users\你的用户名\.codex\config.toml`，没有就自己新建）。

### 2.1 配置骨架

```toml
# 当前用哪个 provider
model_provider = "deepseek"
# 当前用哪个模型
model = "deepseek-chat"

# ---- 定义 provider ----
[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com/v1"
env_key = "DEEPSEEK_API_KEY"        # Key 从这个环境变量读，不要写在这里！

[model_providers.anthropic]
name = "Anthropic"
base_url = "https://api.anthropic.com/v1"
env_key = "ANTHROPIC_API_KEY"

[model_providers.gemini]
name = "Google Gemini"
base_url = "https://generativelanguage.googleapis.com/v1beta/openai"
env_key = "GEMINI_API_KEY"
```

然后设置环境变量（PowerShell，**只对当前窗口有效**）：
```powershell
$env:DEEPSEEK_API_KEY = "sk-你的key"
```
永久生效（**推荐**，但要小心别把 Key 提交到任何地方）：
```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-你的key", "User")
```
设完**要重开一个 PowerShell 窗口**才生效。

### 2.2 切换 provider 的三种方式

| 方式 | 怎么做 | 用途 |
|---|---|---|
| 改配置文件 | 改 `model_provider = "..."` 那一行 | 长期默认 |
| 命令行参数 | 启动时加 `--profile` / `-m` 之类参数 | 临时切 |
| 会话内切换 | 交互模式里输入 `/model` | 最方便，当场换 |

### 2.3 用 profile 一次性记住几套配置（推荐）

```toml
[profiles.deepseek]
model_provider = "deepseek"
model = "deepseek-chat"

[profiles.claude]
model_provider = "anthropic"
model = "claude-sonnet-4-5"   # ⚠️ 模型名以官网当前列表为准

[profiles.gemini]
model_provider = "gemini"
model = "gemini-2.5-pro"      # ⚠️ 同上
```
之后启动时指定 profile 就切换了整套配置。

### 2.4 如果那家不是"OpenAI 兼容"怎么办

三条出路，按优先级：
1. **换一家提供兼容端点的**（大多数厂商都提供，先去它文档里搜 "OpenAI compatible"）
2. 用 `base_url` 指向一个**本地兼容层**（比如把 Anthropic 包装成 OpenAI 格式的小服务）
3. 直接用官方支持列表里的 provider

> **官方核实链接**：Codex 自定义 provider 文档 https://mintlify.wiki/openai/codex/configuration/custom-providers
> （侧边栏还有 `Configuration Reference`，字段有变动以它为准）

## 3. 路线 A-2：让 Claude Code 用别家模型

Claude Code **原生只认 Anthropic 格式**，但官方留了"接入网关"的口子，靠**环境变量**实现。

### 3.1 三个关键环境变量

| 变量 | 作用 |
|---|---|
| `ANTHROPIC_BASE_URL` | 把请求发到哪（默认是 Anthropic 官方地址，改成别人的就换家了） |
| `ANTHROPIC_AUTH_TOKEN` | 给那个地址的凭证（用第三方时填第三方的 Key） |
| `ANTHROPIC_MODEL` / 小模型变量 | 指定主模型和"快速小模型"分别用哪个 |

### 3.2 最简形态

```powershell
# 指向某个提供 Anthropic 兼容端点的服务
$env:ANTHROPIC_BASE_URL = "https://某个服务的地址"
$env:ANTHROPIC_AUTH_TOKEN = "那个服务给你的key"
claude
```

### 3.3 为什么要一个"本地路由"（进阶）

因为**很多家只提供 OpenAI 格式，不提供 Anthropic 格式**。这时需要一个跑在你本机的小程序：
**Claude Code ──(Anthropic 格式)──> 本地路由程序 ──(翻译成 OpenAI 格式)──> DeepSeek/Gemini/…**

社区里有现成的 "claude code router" 类开源项目做这件事（在 GitHub / npm 上搜 `claude-code-router`）。
- ✅ 好处：支持按任务自动路由（简单任务用便宜模型、复杂任务用强模型）
- ⚠️ **风险**：这类项目是**第三方**的，它会拿到你所有代码和 Key。要用就先读它的源码或至少看 issue 区，且**绝对不要**用在工作项目上。npm 上有大量同名/仿冒包，[有安全分析把这类包标为可疑](https://socket.dev/npm/package/@bitkyc08/opencodex)——**装之前先确认作者和仓库地址对得上**。

> **官方核实链接**：Claude Code 网关文档 https://code.claude.com/docs/en/llm-gateway-connect
> 环境变量完整列表：同站 `Reference → Environment variables`（**变量名以官方为准，我上面列的是通用形态**）

## 4. 路线 B：用聚合网关（一次配置，任意换模型）

**原理**：网关对外提供多种格式端点，你自己挑要哪个模型。

典型用法（以 OpenRouter 为例）：
- 在网关注册 → 拿到一个 Key → 充值
- 它同时提供 **OpenAI 兼容端点**和 **Anthropic 兼容端点**，所以 **Codex 和 Claude Code 都能接**
- 换模型 = 改配置里那个模型名字符串

官方有现成的接入教程（**这是最权威的照抄来源**）：
- [OpenRouter × Codex CLI](https://openrouter.ai/docs/cookbook/coding-agents/codex-cli)
- [OpenRouter × Claude Code](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration)
- 它还有 Cursor / OpenCode / Codex Desktop 等一堆同类教程，思路完全一样

## 5. 路线 C：什么都不用配——你已经有的方案

**别忘了**：你第 7 周要亲手写的那个 `multi-model-cli`（Node.js 脚本，`Day 46～47`），本质就是**你自己的最小网关**。

```
你的脚本 → 读一个配置文件 → 决定这次问哪家 → 调对应 API → 打印结果
```

它的意义比"配好一个工具"大得多：
- 你会真正理解 **API 是通用的、工具只是壳**
- 以后任何新工具出了，你都能 20 分钟接上自己的模型
- 你可以做成**对比工具**：同一个问题同时问三家，并排看答案（这是练"多模型判断力"最好的工具）

**建议的顺序**：
```
Day 46～47 写自己的 multi-model-cli  →  搞懂原理
     ↓
再回来配 Codex / Claude Code 的第三方 provider  →  发现"原来就是填个地址"
     ↓
（可选）最后才试聚合网关和本地路由  →  知道什么时候值得用
```

## 6. ⚠️ 三条政策与法律红线（很多人在这翻车）

### 6.1 订阅账号不能拿来这么干

- **Claude 的网页/App 订阅**、**Claude Code 的订阅套餐**、ChatGPT 的订阅：官方文档明确说明这类托管产品**只能走官方通道**，把订阅凭证指到别处是**违反服务条款**的，可能直接封号。
- **正确做法**：第三方模型一律用**该家的 API Key**（按量付费），不要动订阅的凭证。
> 一句话：**订阅是"堂食"，API Key 是"外卖"**，不能拿堂食的票去点外卖。

### 6.2 中转服务可能泄露你的全部代码

走第三方网关时，你的**源码、密钥、项目结构**全部经过别人的服务器。
- 学习项目：可以接受
- 有商业价值的项目：**不要**

### 6.3 别把 Key 写进配置文件

配置文件（`config.toml`、`.env`）**永远不要提交到 GitHub**。
- Codex 的设计就很好：配置里只写**环境变量的名字**（`env_key = "DEEPSEEK_API_KEY"`），真 Key 在系统环境变量里。
- 如果你非要写在项目里，**必须**把 `.env` 加进 `.gitignore`。

## 7. 30 分钟上手路径（照着做）

### 第 1 步：准备两家的 API Key（10 分钟）
- DeepSeek：https://platform.deepseek.com/ （便宜，适合天天用）
- 另一家自选：OpenAI / Anthropic / Google
- **每家的后台都设置"用量上限"**，这比什么都重要

### 第 2 步：先不碰任何工具，用一条命令验证 Key 是好的（5 分钟）

在 PowerShell 里（把 Key 换成你的）：
```powershell
$env:DEEPSEEK_API_KEY = "sk-你的key"

curl.exe https://api.deepseek.com/v1/chat/completions `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer $env:DEEPSEEK_API_KEY" `
  -d '{\"model\":\"deepseek-chat\",\"messages\":[{\"role\":\"user\",\"content\":\"说一句你好\"}]}'
```
看到返回 JSON 里有回复内容 → Key 和网络都没问题。
**这一步能省你后面 90% 的排查时间**：如果这里就失败，问题在 Key / 网络 / 余额，跟工具无关。

> 为什么用 `curl`：它让你看到**原始的请求和响应**。以后任何工具报"认证失败/模型不存在"，你都能用这条命令判断"到底是工具的锅还是 Key 的锅"。

### 第 3 步：配置 Codex（10 分钟）
1. 打开 `C:\Users\你的用户名\.codex\config.toml`（没有就新建）
2. 按本文第 2.1 节写 provider（先只配一家）
3. 设好环境变量 → **重开 PowerShell**
4. 启动 Codex，问它"你现在用的是哪个模型"，或用它自带的诊断/状态命令确认
5. 成功后再加第二家、第三家

### 第 4 步：配置 Claude Code（5 分钟）
1. 按第 3.2 节设 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN`
2. 启动 `claude`，随便问一句
3. 失败就回到第 2 步，用 `curl` 打那个 `BASE_URL` 看通不通

### 第 5 步：记录（必做）
在 `学习日志.md` 里记：

## 8. 排查清单（按这个顺序查，别乱试）

| 现象 | 先查什么 |
|---|---|
| 认证失败 / 401 | Key 拼错？环境变量设置后**没重开终端**？余额为 0？ |
| 模型不存在 / model not found | 模型名写错了。**去官网看当前真实模型名**，不要抄教程里的（教程常常过时） |
| 连接超时 / 网络错误 | base_url 写错？公司/校园网限制？需要代理？ |
| 返回内容像是别家模型 | 你在用中转服务，可能被"偷换模型"。换回官方 Key 对比 |
| 工具完全不认这个 provider | 这个工具只支持特定协议（比如 Claude Code 只认 Anthropic 格式）→ 需要网关翻译 |
| 昨天还能用今天不行了 | 上游改政策/改模型名了。去看官方 changelog |

**通用判断法**：
1. 先用 `curl` 直连 API 成功 → 说明 Key 没问题，问题在工具配置
2. `curl` 也失败 → 问题在 Key / 网络 / 余额 / 模型名
