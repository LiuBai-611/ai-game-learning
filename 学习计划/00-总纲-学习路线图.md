# AI 小白 → 多模型熟练者 → AI 编程独立游戏开发者：总纲路线图

> 适用对象：非计算机专业、不会 Python / C++、只用过网页与 App 对话模型的人。
> 目标终点：能熟练调度多个 AI 模型，用 AI 编程独立完成并发布一款小游戏。
> 配套文件：`01-12周每日任务表.md`（逐日执行）、`02-GitHub学习项目库.md`（可下载项目）、`03-AI协作提示词库.md`（直接复制粘贴）、`04-术语词典.md`（你列的词全部解释）、`05-环境搭建清单.md`（装什么、怎么装）。

---

## 0. 先看这一页：三个必须纠正的认知

**认知一：你不需要"先学编程，再用 AI"。**
传统路线是"学语法 → 写代码 → 做项目"，需要 2～3 年。你的路线是反过来的：

```
有想法 → 让 AI 写出能跑的代码 → 运行看结果 → 让 AI 解释这段代码 → 自己动手改一个数值/一行 → 再让 AI 检查
```

这叫**"AI 领读式编程"**。你不是从语法开始，而是从"能跑起来的东西"开始，语法是在解释和改动中被动学会的。这条路走得通的前提是：**你必须运行、必须看报错、必须改一行再跑一次**——只看不跑，AI 帮不了你。

**认知二：你不能跳过"读懂代码"这一步。**
AI 能写出代码，但代码跑不起来时，只有你能描述"哪里不对"。第 4 周开始，每天的固定动作就是"读懂今天 AI 写的每一行"。目标是 12 周后你能看懂 80% 的 GDScript，而不是永远当"只会复制粘贴的人"。

**认知三：语言只要学一门，就是 GDScript。**
Godot 用 GDScript（语法和 Python 极像，但更简单，专为游戏设计）。不要同时碰 Python 和 C++。附带的网页/接口部分用 **JavaScript（Node.js）**，因为你的电脑已经装好了 Node，且 AI 生成 JS 的质量最高。整条路线只有 **GDScript + 一点点 JS**，两门，都是脚本语言，不是 C++。

## 1. 路线总览：四个阶段

| 阶段 | 时间 | 身份转变 | 核心产出 | 验收标准 |
|---|---|---|---|---|
| **P0 奠基** | 第 1～2 周 | 使用者 → 会配置的进阶使用者 | 多模型账号矩阵、GitHub 仓库、开发环境 | 能用 3 个模型对比同一问题并说出各自差异 |
| **P1 引擎入门** | 第 3～5 周 | 玩家 → 会做小 demo 的人 | 5 个能跑的小游戏 demo | 能从零（不看教程）做出"人物会走 + 会跳 + 会撞墙"的场景 |
| **P2 AI 协作与美术** | 第 6～8 周 | 会做 demo → 会做完整小游戏 | 一份可玩的垂直切片（Vertical Slice） | 用 AI 生成素材 + AI 写代码，做出有菜单、有音效、有胜负判定的关卡 |
| **P3 独立游戏与发布** | 第 9～12 周 | 会做 → 能发布 | **一款完整可玩、有商店页面的小游戏 + 一个 AI 技能作品** | 有人（非你自己）下载并玩超过 5 分钟 |

**每周节奏（固定不变）**：
- 周一至周五：每日 1.5～2 小时，做当天任务
- 周六：2～3 小时，做"本周整合任务"（把小练习合成一个东西）
- 周日：休息 / 只做 30 分钟复盘（填写 `01` 文件末尾的周复盘表）

**每天雷打不动的三段式（1.5 小时版）**：

| 时段 | 时长 | 做什么 |
|---|---|---|
| ① 运行 | 10 分钟 | 打开昨天的项目，跑一遍，确认没坏 |
| ② 造 | 60 分钟 | 今天的核心任务（AI 写 → 你跑 → 改 → 再跑） |
| ③ 讲 | 20 分钟 | 选今天 10 行代码，让 AI 逐行讲解，你再用自己的话写进 `学习日志.md` |

> 第 ③ 段是全部计划里最重要的一段。删掉它，12 周后你还是小白。

## 2. 工具矩阵：用什么、什么时候用、为什么

### 2.1 对话与编程模型（网页/App 就能开始）

| 工具 | 你的用途 | 什么时候引入 | 备注 |
|---|---|---|---|
| **ChatGPT** | 通用答疑、概念解释、脑暴、图像（ChatGPT Images） | 第 1 天 | 概念不懂时问它，要求"用初中生能懂的话 + 一个生活比喻" |
| **Claude** | 长文档阅读、代码质量、复杂项目重构 | 第 1 周 | 给它整份项目文件让它做审查，表现最好 |
| **DeepSeek** | 便宜、量大、中文强、代码不错 | 第 1 周 | 日常大量问答用这个省额度 |
| **Codex / Claude Code / 各类 Agent 工具** | 直接改你电脑上的文件、跑命令 | 第 2 周起 | 这才是"AI 编程"的真正形态：不是聊天，是**让 agent 进你的项目文件夹干活** |
| **Gemini** | 长上下文、图片视频理解、Google 生态 | 第 3 周 | 可选 |

> **重要提醒**：你列表里的"Claude Opus 5.5""GPT-6 astra"这类**具体版本号我无法确认存在**，模型版本每一两个月就变一次，网上流传的版本名大量是假的或提前泄密的代号。正确做法是：每周花 5 分钟打开各家官网的 Models / Pricing 页面，看当前实际有哪些模型、多少钱，记到 `学习日志.md` 里。**不要记版本号，要记"什么任务该用哪一类模型"**：
> - 需要最强推理 / 最难的 bug → 旗舰模型（贵，按次用）
> - 日常问答、批量改写、翻译 → 中端模型（便宜，随便用）
> - 简单分类、格式化、长文摘要 → 轻量模型（最便宜，可自动化）
>
> 这套"分级用模型"的判断力，就是**"多模型运用"的真正含义**，也是本计划 P0 阶段的重点。

### 2.2 开发环境（这台电脑的现状我已检查）

| 项目 | 当前状态 | 需要做什么 |
|---|---|---|
| Node.js / npm | ✅ 已安装（`D:\124\New Folder\node.exe`） | 无需安装，直接用 |
| Git | ❌ 未安装 | **第 1 天第一件事**：装 Git + GitHub Desktop |
| Godot | ❌ 未安装 | 第 2 周装 Godot 4.x（标准版，不是 .NET 版） |
| VS Code | ❌ 未安装 | 第 1 周装（写 JS / 看代码用），可选 |
| Python | ⚠️ 只有 Windows 商店的占位程序 | **不要装**。本计划全程不需要 Python |

详见 `05-环境搭建清单.md`。

### 2.3 游戏引擎：为什么选 Godot

- 免费、开源、无水印、无版税，商用无门槛
- 安装包只有 100 多 MB，解压即用，比 Unity 轻得多
- 场景系统可视化，**不写代码也能拖出一个能跑的东西**，对小白友好
- 原生支持 2D，做《Tiny Swords》这类像素风小游戏非常合适
- AI（尤其是 Claude / GPT）对 GDScript 的生成质量很高，因为语法简单、文档齐全

**不做 3D 起步**。第 12 周之后如果还想深入渲染/网页 3D，再学 `three.js`（JavaScript 的 3D 库，能在浏览器里跑 3D）。它属于"锦上添花"，不是主线——先做出 2D 游戏发布，再考虑它。

## 3. 十二周里程碑（详细每日任务见 `01` 文件）

### P0 奠基（第 1～2 周）
- **W1**：环境 + Git + GitHub + 多模型矩阵。产出：你的第一个 GitHub 仓库（里面放学习日志）。
- **W2**：GitHub 找项目、下载、看懂目录结构；学会"把一个开源 Godot 项目跑起来"。产出：本地跑通 2 个别人的 Godot 项目。
- **里程碑 M0**：你能独立完成"从 GitHub 下载项目 → 用 Godot 打开 → 运行成功 → 找到某个数值改掉"。

### P1 引擎入门（第 3～5 周）
- **W3**：Godot 界面 + 节点（Node）+ 场景（Scene）概念 + 第一个"能动的方块"。
- **W4**：GDScript 读代码训练 + 玩家移动、跳跃、碰撞。
- **W5**：动画、TileMap 地图、敌人、碰撞检测、分数系统。
- **里程碑 M1**：不看教程，独立做出"一个角色在地图里跑跳、撞到敌人扣血、吃金币加分"的小 demo。

### P2 AI 协作与美术（第 6～8 周）
- **W6**：游戏美术基础 + AI 生图 + 素材库使用 + **版权License 判读**（这一步很多人跳过，会在发布时踩坑）。
- **W7**：UI / 菜单 / 音效 / 存档 + 用 Agent 工具（Codex 类）重构整个项目。
- **W8**：做一个"垂直切片"：把前面所有零件组装成一个 10 分钟可玩的关卡。
- **里程碑 M2**：一个有开始界面、能玩、有胜负、有音效、能重开的完整关卡。

### P3 独立游戏与发布（第 9～12 周）
- **W9**：确定你的小游戏题材（用"最小可玩"原则砍功能）+ 写设计文档。
- **W10**：实现核心玩法循环。
- **W11**：打磨：手感、镜头、UI、教程引导、bug 修复。
- **W12**：导出 Windows 可执行文件，发布到 itch.io，写商店页；同时把 P0～P2 积累的 AI 工作流整理成你的"个人 AI 工具箱"。
- **里程碑 M3**：**有人下载并玩了你的游戏**。这一个动作，就让你从"学习者"变成"开发者"。

## 4. "熟练运用多模型"到底怎么练

这不是"多用几个 App"，而是四个层级，每周都在升级：

| 层级 | 名称 | 表现 | 计划中在哪练 |
|---|---|---|---|
| L1 | 会用 | 知道有哪些模型，会开关账号 | W1 |
| L2 | 会挑 | 同一个问题知道派谁去，会对比 | W1～W2，每天"三模型对比"作业 |
| L3 | 会管上下文 | 会写系统提示、会喂文件、会切分任务、会控制上下文长度 | W4 起，`03-提示词库.md` 全程使用 |
| L4 | 会接 API / 会编排 | 会用 API 把模型接进自己的程序；会用 Skill / MCP / Agent 工作流让模型自动干活 | W7～W12 的支线任务 |

**必须理解的三个词**（详细解释见 `04-术语词典.md`）：
- **API**：让"程序"而不是"人"去跟模型说话的通道。你在网页上打字是人在问；API 是你的代码自动去问。有 API 才能自动化、批量、接进游戏。
- **Skill**：给 AI 预先写好的一份"技能说明书"，让它遇到某类任务时自动按你的规范做。
- **MCP（Model Context Protocol）**：一套开放标准，让 AI 能安全地读取你电脑上的文件、调用你的工具。它是"AI 从聊天走向干活"的关键协议。

## 5. GitHub 怎么用（你的核心资源库）

**不要"随便找项目看"**，那是最容易放弃的学法。按这个顺序：

1. **先找"能跑的完整项目"**，不是"教程代码片段"。目标：下载 → 打开 → 按 F5 就能跑。
2. **跑通之后再读**。读的顺序永远是：`README` → 文件夹结构 → 入口场景 → 主脚本 → 你感兴趣的那个功能。
3. **每个项目必须留下痕迹**：在 `学习日志.md` 里写三行——"这个项目做了什么 / 我看懂了什么 / 我改了哪里"。
4. **改动是最快的学法**：把跳跃高度改成 5 倍、把敌人速度改成 0.1 倍、把金币变成扣分。看会发生什么。

计划中指定的项目清单、下载方式、以及"每个项目该重点看什么"，全部在 **`02-GitHub学习项目库.md`**。

## 6. 每日任务的写法（`01` 文件的结构说明）

`01-12周每日任务表.md` 里，每一天都是这个格式：

```
### Day 07 ｜ 主题 ｜ 预计 90 分钟
🎯 目标：（今天结束后你会什么）
📦 需要：（下载/打开什么）
▶ 步骤：
   1. ...
   2. ...
🤖 让 AI 干什么：（可直接复制的提示词，或指向 03 文件的编号）
✅ 交付物：（今天必须产出的东西，没有交付物=今天没完成）
❗ 常见坑：
```

**规则**：
- **交付物是硬性的**。哪怕只是"一张截图 + 三行笔记"也算，但必须存在。
- **卡住超过 40 分钟就换策略**：不要死磕。把报错原文整段复制给 AI，问"这是什么意思、我该改哪里"。还不行就跳过，在日志标记"待解决"，周末统一处理。
- **允许落后，不允许跳过"运行"这一步**。落后的部分周末补，但每天必须让代码跑起来一次。
