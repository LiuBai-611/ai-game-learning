## 0. 先解决网络（比装任何软件都重要）

**Day 01 实测结论**：本机直连 GitHub 的**下载通道会被阻断**（网页能开，但 clone / Download ZIP 经常超时）；Git 的浏览器授权弹窗也反复失败。
这不是你操作错了，是网络环境问题。**先固化下面三个方案，否则后面 20 多次"下载"动作都会卡。**

### 0.1 Git 克隆走镜像（已验证可用）
克隆别人的项目时，把 `github.com` 换成镜像站。常用两个：
```bash
# 清华镜像
git clone https://mirrors.tuna.tsinghua.edu.cn/git/<作者>/<仓库>.git

# ghproxy 加速（在原始地址前加前缀）
git clone https://ghproxy.net/https://github.com/<作者>/<仓库>.git
```
> 注意：镜像站**不一定收录**任意仓库。收不到时用 ghproxy；两个都不行就换 0.2。

### 0.2 下载 ZIP 用加速（Day 11 / 23 / 26 / 36 / 49 会反复用到）
```
https://ghproxy.net/https://github.com/<作者>/<仓库>/archive/refs/heads/main.zip
```
把原始 `github.com/.../archive/...zip` 地址前面拼上 `https://ghproxy.net/` 即可。

### 0.3 Godot 与导出模板的备用下载
- Godot 官网下载慢时，去 **GitHub Release** 下（用 0.2 的加速）：`godotengine/godot` 仓库的 Releases 页。
- **导出模板**（Day 34 导出 exe 时必需，几百 MB～1 GB）同样在 Release 页，文件名形如 `Godot_v4.x-stable_export_templates.tpz`。
  > ⚠️ 导出模板**不要等到 Day 34 才下**。建议 Day 08 装 Godot 时顺手一起下好，存进 `D:\dev\_installers\`，否则第 5 周导出时会因为网络卡住半天。

### 0.4 Git 认证：用 Token，别跟弹窗死磕
Day 01 实测：浏览器授权（GCM OAuth）反复被打断。**改用 Personal Access Token**：
1. GitHub → 右上角头像 → `Settings` → `Developer settings` → `Personal access tokens` → `Tokens (classic)` → `Generate new token`
2. 勾选 `repo` 权限，生成后**立刻复制**（页面关掉就再也看不到）
3. 第一次 `git push` 提示输入密码时，**粘贴这个 Token**（不是账号密码）
4. Windows 会存进「凭据管理器」，之后不用再输

> Token 等于密码，**绝不能**写进代码、贴进聊天、提交到 GitHub。

### 0.5 什么时候该怀疑是网络问题
出现下面任一现象，先别改代码，先按 0.1～0.3 换通道：
- `git clone` 卡在 `Receiving objects` 很久，然后 `RPC failed` / `early EOF`
- 浏览器下载 GitHub 的 zip 只有几十 KB/秒，或直接失败
- `fatal: unable to access ... Failed to connect to github.com`

## G. 新手环境三大坑（提前避开）

1. **路径里有中文或空格** → Godot、Node 脚本、命令行工具都可能出错。
   正确：`D:\dev\my-game` ❌错误：`C:\Users\我 的文档\游戏 项目`
2. **Godot 3 和 4 的教程混着看** → 报错满天飞，还找不到原因。**只学 4.x**，并且锁死小版本（见 C2）。
3. **把 API Key / 密码提交到 GitHub** → 会被爬虫秒扫，几小时内被盗刷。记住：**凡是密钥，一律 `.env` + `.gitignore`**。
4. **⚠️ 本机的一个已知例外**：Node.js 装在 `D:\124\New Folder\node.exe`，**这个路径带空格**，和上面第 1 条铁律冲突。
   - 现在不用管（Day 46 之前用不到 npm 装包）。
   - 到了 **Day 46 装依赖**时如果报奇怪的路径错误，就是这个原因。两个解法：① 重装 Node 到 `D:\dev\node\` 这类无空格路径；② 用 `npm --prefix` 指定安装目录。
   - **新建的任何项目，仍然严格遵守"无中文、无空格"。**
5. **Windows PowerShell 5.1 读写带中文的文件会乱码**（2026-10-10 实测发现）。
   - 这台机器上 `powershell` 是 **5.1 版**，它对**没有 BOM 的 UTF-8 文件**默认按 GBK 解码，所以 `Get-Content 学习日志.md` 可能显示成一堆 `閿欒` 这样的怪字，甚至**看起来少了几行**（文件本身没坏，只是显示坏了）。
   - **危险动作**：`Get-Content x.md | Set-Content y.md`、`(Get-Content x) -replace ... | Set-Content x` —— 这会把乱码**真的写回文件**，中文全毁。
   - **安全做法**：① 看/改中文文本用 VS Code（不是命令行）；② 非要用命令行，加 `-Encoding UTF8`：
     ```powershell
     Get-Content .\学习日志.md -Encoding UTF8
     ```
   - **判断文件到底坏没坏**：在 VS Code 里能不能正常显示。Git 里的字节是好的，就别管命令行的显示。
