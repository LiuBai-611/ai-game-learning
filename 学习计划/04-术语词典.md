## 一、你列表里的词（逐个拆解）

### 1. Godot 引擎 ✅⭐
免费开源的游戏引擎，本计划全程使用。特点：安装包小（100 多 MB，解压即用）、免费商用无版税、2D 支持好、用 GDScript 写代码（语法简单）。
- 官网：https://godotengine.org/
- **关键必须记住的一点**：Godot 3 和 Godot 4 代码几乎不通用。学的时候只认 4.x。
- 为什么选它而不是 Unity：对非科班小白更友好，没有安装器和账号门槛，学习曲线平缓。

### 2. 素材库 / 游戏素材（Game Assets）✅⭐
游戏里用到的所有"非代码资源"：图片（角色、场景、UI、图标）、音频（音效、音乐）、字体。
常见来源：Kenney.nl（全 CC0）、itch.io/game-assets、OpenGameArt、freesound。
- **核心知识点不是"去哪下载"，而是"License（授权）"**：能不能商用、要不要署名、能不能改。三个都搞清楚才能用。
- 详见 `02-GitHub学习项目库.md` 的 #5。

### 3. Tiny Swords ⚠️
一个很有名的免费 2D 游戏素材包（在 itch.io 上，作者 Pixel Frog），美术风格清爽，非常适合做中世纪/塔防/策略类小游戏。**这是素材包，不是游戏引擎。**
- **重要提醒**：这个素材包的**授权条件历史上做过调整**，社区里对"能否用于商业游戏"有大量讨论，不同版本的条件可能不同。
- **你必须做的事**：使用前打开它 itch.io 页面上作者写的授权说明**原文**，自己读一遍。**不要相信任何二手转述（包括其他教程、群聊、我这句提醒）**。
- 参考讨论（作为"有争议"的证据，而不是结论）：
  - [Licensing on open source projects — Tiny Swords community](https://itch.io/t/5783521/licensing-on-open-source-projects)
  - [Asset usage for commercial game (Tiny Swords + Enemy Pack)](https://itch.io/t/6181528/asset-usage-for-commercial-game-tiny-swords-enemy-pack)

### 4. 游戏美术 ✅⭐
游戏里视觉部分的总称。独立开发者需要掌握的不是"画得好"，而是：
- **统一**：所有素材的色调、分辨率、线条风格一致（用统一调色板最容易做到）
- **清晰**：玩家一眼能分清"哪个是我、哪个是敌人、哪个能捡"
- **反馈**：动作有反馈（击中闪光、受伤抖屏、加分数值弹出）
> 第 6 周（Day 35～41）专门练这个。

### 5. AI 编程 ✅⭐
**不是**"让 AI 写代码给你复制"，而是三件事的组合：
1. **AI 生成**：描述需求 → AI 写代码
2. **AI 解释**：把代码给 AI → 你读懂它（这才是你成长的部分）
3. **AI 操作**：让 Agent 直接读改你项目里的文件、跑命令、修 bug
本计划中，第 1～6 周主要用 1+2，第 7 周起重点转向 3。

### 6. 智能体运用（AI Agent）✅⭐
**Agent = 能自己动手干活的 AI**，不只是聊天。
- Chat 模式：你问，它答，你自己复制粘贴
- Agent 模式：它有工具，能读你的文件、写文件、运行命令、看结果，再决定下一步
**铁律**：让 Agent 改你的项目前，**先在 Git 里 commit 一次**。这样改坏了一个命令就能回滚。

### 7. 多模型使用 ✅⭐
**不是**"多注册几个账号"，而是四个层级（这是本计划 P0 阶段的核心）：
| 层级 | 表现 |
|---|---|
| L1 会用 | 知道有哪些模型 |
| L2 会挑 | 知道什么任务派谁（最难的 bug → 旗舰模型；批量翻译 → 便宜模型） |
| L3 会管上下文 | 会写提示词、会喂文件、会切分任务、知道什么时候开新对话 |
| L4 会编排 | 会用 API 把模型接进程序；会用 Skill / MCP 让 AI 自动干活 |

### 8. API ✅⭐
**程序之间的说话接口**。你在网页上打字 = 人在问；API = 你的代码自动去问。
- 用途：批量处理、接进自己的程序、做自动化工具、让游戏里有 AI 功能
- 要有 **API Key**（一串密钥）才能用，而且**按用量收费**
- **安全三条**：① Key 放在 `.env` 文件里 ② `.env` 写进 `.gitignore` ③ 平台里设置用量上限
- **绝对禁止**：把 Key 写进代码、发到聊天里、提交到 GitHub（会被爬虫几秒内扫走并盗刷）
- 第 7 周 Day 46～47 你会亲手跑通第一个 API 调用（用 Node.js，不需要 Python）

### 9. Codex / Agent 工作流 ✅
"Codex" 现在泛指**命令行式/IDE 式的 AI 编程代理工具**（能直接操作你的项目文件）。各家名字不同，但用法一致：
1. 给它一个明确的任务
2. 限定它能改哪些文件
3. 要求它改完跑一遍验证、报告改了哪些文件
- ⚠️ **这类工具命名和形态变化极快**（今天叫这个名字，下个月可能改名或合并进别的产品）。**跟着"能力"走，不要跟着"名字"走**。
- 关键配套文件：`AGENTS.md`（给 AI 看的项目说明书，见 `[P-44]`）

### 10. Claude ✅⭐
Anthropic 公司的 AI 模型系列，公认强项：长文档理解、代码质量、复杂重构。
- ⚠️ **版本号提醒**：你写的"Claude Opus 5.5"**我无法确认存在**。这类具体版本号在网络上真假混杂（有官方名、有内部代号、有编造的）。**正确做法**：要用之前打开 https://www.anthropic.com/ 或它的定价页，看当前实际可用的模型名和价格。**不要记版本号，要记"这个模型适合干什么"**。

### 11. 接入多模型 API ✅⭐
指用一套代码同时调用多家模型（比如一个脚本能问 DeepSeek、OpenAI、Claude）。
- 为什么有用：**同一个问题问三家，比较答案**——这是提升判断力最快的办法；也能按成本自动挑最便宜的模型。
- 你在 Day 47 会做出这个东西：`multi-model-cli`。

### 12. 知识库（Knowledge Base / RAG）✅
**让 AI 基于你的资料回答问题**的技术。因为模型本身不知道你的项目细节，所以要把你的文档"喂"给它。
- 简单做法：直接把文档贴进对话（小项目够用）
- 进阶做法：RAG（检索增强生成）——把文档切成小块存进向量库，提问时自动检索相关片段再喂给模型
- 对你的实际用途：把你的 `学习日志.md`、`godot笔记/`、`design/GDD.md` 喂给 AI，它就能当"了解你项目的助手"

### 13. Skill ✅
**给 AI 预先写好的"技能说明书"**。让 AI 在遇到某类任务时自动按你的规范做，而不用你每次重复交代。
- 例子：写一个"Godot 代码规范"的 Skill，以后每次让它写代码都自动遵守你的命名和注释习惯。
- 和 `AGENTS.md` 的区别：`AGENTS.md` 是项目级的规矩；Skill 是可以跨项目复用的能力包。
- **本质**：把你重复说过 10 遍的要求，固化成一个文件。这就是"工作流"的起点。

### 14. Claude Opus 5.5 ❓
**我无法确认这个具体版本存在。** Opus 是 Anthropic 的旗舰模型名（Opus 确实存在），但"5.5"这个版本号我在公开信息里无法核实。
→ **行动**：去 https://www.anthropic.com/ 官网查当前模型列表。**以后遇到任何"XX 模型第 N 代"的说法，都去官网核实**。

### 15. GPT-6 astra ❓
**我无法确认这个存在。** GPT 是 OpenAI 的模型系列（确实存在），但"GPT-6"和"astra"我无法核实是否为官方正式名称——网络上有大量关于未来版本的传闻和代号。
→ **行动**：去 https://platform.openai.com/docs/models 看官方当前模型列表。

### 16. ChatGPT ✅⭐
OpenAI 的对话产品（网页/App）。本计划中它的用途：通用答疑、概念解释、脑暴。

### 17. ChatGPT Images ✅
ChatGPT 的图像生成能力（底层是图像生成模型）。
- 适合：概念图、UI 草图、图标、参考图、商店页宣传图素材
- **不适合**：逐帧动画精灵图（AI 目前做不好帧间一致性）
- ⚠️ 生成内容的**商用权利条款各平台不同且会变**，商用前必须查最新条款，并记进你的 `godot笔记/05-素材许可.md`

### 18. three.js ✅
JavaScript 的网页 3D 图形库，能在浏览器里跑 3D（官网 https://threejs.org/）。
- 用途：网页 3D 小游戏、3D 作品集展示、产品展示页
- **什么时候学**：**做完并发布你的 2D 游戏之后**（第 12 周以后）。现在学它会分散你的注意力，而且它不能帮你更快做出第一款游戏。
- 入门参考：[MDN 的 three.js 基础教程](https://developer.mozilla.org/zh-CN/docs/Games/Techniques/3D_on_the_web)

### 19. WorkBuddy ✅（已核实）
**腾讯**推出的 AI Agent 桌面工作台，办公场景向（腾讯云 CodeBuddy 团队的产品）。
- 官网（**唯一官方下载渠道**）：https://www.codebuddy.cn/work/
- Windows 版是 `WorkBuddySetup.exe`（约 150–180 MB），**图形安装向导 + 必须登录腾讯账号**，无法用命令行静默安装
- 能力：Office/PDF 文件批量处理、多模型切换（混元 / DeepSeek / GLM / Kimi 等）、通过企业微信/QQ/飞书/钉钉远程操控电脑、兼容 OpenClaw 技能生态
- ⚠️ **安全提醒**：网络上存在多个叫 "WorkBuddy" 的东西。**只从 `codebuddy.cn` 官方域名下载**；任何"破解版/汉化版/网盘直链"一律不要装。安装后它要求读写你的文件，**只授权必要文件夹**。
- ⚠️ **和你的主线目标不完全一致**：WorkBuddy 偏**办公自动化**（合并 Excel、转 PDF、生成 PPT），而你要做的是**独立游戏开发**——那个活用 Codex / Claude Code 更对口。**工具越多，配置和踩坑成本越高，做游戏的时间不会因此变多。**
- 详见 `.tools\README.md`

## 二、GitHub 与版本管理

| 术语 | 一句话解释 |
|---|---|
| **Git** ⭐ | 版本管理工具，记录你每次改了什么，能回滚。装在本机上 |
| **GitHub** ⭐ | 存放 Git 仓库的网站。你的代码作品集和备份 |
| **仓库（Repository / repo）** | 一个项目文件夹，被 Git 管理着 |
| **commit** ⭐ | 一次"存档"。把当前改动记录下来，附一句说明 |
| **push / pull** ⭐ | push = 把本地存档上传到 GitHub；pull = 把 GitHub 上的更新拉到本地 |
| **branch（分支）** | 从主线分出来的平行版本，用来试验而不影响主线。新手前 6 周可以不用 |
| **clone** | 把 GitHub 上的仓库完整复制到本机 |
| **fork** | 把别人的仓库复制一份到你自己的账号下（改别人的项目时用） |
| **.gitignore** ⭐ | 一个文件，列出"不要提交"的文件（缓存、密钥、导出文件） |
| **README.md** ⭐ | 项目的说明书。别人（和三个月后的你）靠它知道这项目是什么、怎么跑 |
| **License（开源许可）** | 授权条款。见下方"素材与法律" |
| **star** | 收藏/点赞，也是衡量项目热门度的指标（但**不等于质量**） |

## 三、Godot 核心概念

| 术语 | 一句话解释 |
|---|---|
| **项目（Project）** ⭐ | 一个游戏，最小单位。有一个 `project.godot` 文件标识它 |
| **场景（Scene）** ⭐ | 可复用的"零件"，存为 `.tscn`。可以是一个角色、一个关卡、一个 UI 面板 |
| **节点（Node）** ⭐ | 场景里的基础积木。相机、精灵、碰撞体、定时器都是节点 |
| **节点树** ⭐ | 节点按父子关系组成的树。**缩进就是父子关系**，父节点动子节点跟着动 |
| **脚本（Script）** ⭐ | 挂在节点上的代码，`.gd` 文件。**代码不是独立存在的，它属于某个节点** |
| **GDScript** ⭐ | Godot 的官方脚本语言。语法和 Python 很像，专为游戏设计 |
| **信号（Signal）** ⭐ | 节点之间"广播消息"的机制。发出方不用知道谁在听（解耦的关键） |
| **@export** ⭐ | 加在变量上，让它在编辑器检查器里可以直接调，不用改代码 |
| **Autoload（单例）** ⭐ | 全局唯一的脚本，跨场景保存数据（分数、设置） |
| **CanvasLayer** | 一层不受相机影响的画布。**HUD 必须放在它下面** |
| **TileMap / TileSet** | 用瓦片拼地图的系统 |
| **Collision Layer / Mask** ⭐ | Layer = 我属于哪个频道；Mask = 我听哪些频道。**新手最大的坑** |
| **CharacterBody2D** | 用代码控制移动的角色物理体（平台跳跃用它） |
| **Area2D** | 只检测"谁进来了"的感应区（金币、伤害区、视野） |
| **StaticBody2D** | 不动的物理体（地面、墙） |
| **RigidBody2D** | 完全交给物理引擎的物体（会被撞飞） |
| **_ready / _process / _physics_process / _input** | 生命周期函数：开始时 / 每帧 / 固定间隔物理帧 / 输入事件 |
| **delta** ⭐ | 上一帧到这一帧的秒数。速度乘上它才能在快慢电脑上表现一致 |
| **move_and_slide()** | CharacterBody2D 的移动并处理碰撞的方法 |
| **is_on_floor()** | 判断是否站在地面上（要放在 move_and_slide 之后才准） |
| **instance（实例化）** | 把场景当模板"复制"出一个来用 |
| **queue_free()** | 把一个节点安全地删除 |
| **Tween** | 做补间动画（淡入淡出、数值渐变） |
| **res:// 与 user://** ⭐ | `res://` = 项目文件夹内；`user://` = 系统给的存档目录（存档必须用它） |
| **导出（Export）** | 把项目打包成 exe/apk 等可执行文件给别人玩 |

## 四、AI 与开发通用概念

| 术语 | 一句话解释 |
|---|---|
| **Token** ⭐ | AI 计费和计算的基本单位，约等于"一个词/半个汉字"。上下文长度和费用都按它算 |
| **上下文窗口（Context Window）** ⭐ | AI 一次能"看到"的最大信息量。**满了就开始忘事、变笨** |
| **提示词（Prompt）** ⭐ | 你给 AI 的指令。写得好坏直接决定输出质量 |
| **系统提示（System Prompt）** | 在对话最前面设定 AI 角色和规则的指令 |
| **温度（Temperature）** | 控制随机性。低=稳定保守（写代码用低的），高=发散有创意（脑暴用高的） |
| **幻觉（Hallucination）** | AI 一本正经地编造不存在的东西（假版本号、假的 API 用法）。**必须自己验证** |
| **RAG / 知识库** | 让 AI 先查你的资料再回答的技术 |
| **MCP（Model Context Protocol）** ⭐ | 开放协议，让 AI 能安全读取你的文件、调用你的工具。AI "从聊天走向干活"的关键 |
| **Agent（智能体）** ⭐ | 能自主使用工具、多步骤完成任务的 AI |
| **Skill** ⭐ | 预先写好的技能说明书，让 AI 自动按你的规范干活 |
| **Function Calling / Tool Use** | 让 AI 能调用函数/工具（查天气、读文件）的能力 |
| **Cursor / IDE 集成** | 把 AI 直接嵌进代码编辑器里 |
| **Node.js** ⭐ | 让 JavaScript 在电脑上跑（不只在浏览器里）的运行环境。**你电脑已装好** |
| **npm** | Node.js 的包管理器，用来一行命令装别人写好的库 |
| **.env 文件** ⭐ | 存放密钥等敏感信息的文件。**必须加进 .gitignore** |
| **环境变量** | 从系统层面传给程序的配置值（常用来存密钥） |
| **SDK / 库（Library）** | 别人写好的代码包，你直接调用，不用重造轮子 |
| **JSON** | 一种数据格式，人和机器都好读。存档、API 交互常用 |
| **Markdown（.md）** ⭐ | 用简单符号排版的纯文本格式。你所有笔记都用它，GitHub 能直接渲染 |

## 五、游戏开发通用概念

| 术语 | 一句话解释 |
|---|---|
| **核心循环（Core Loop）** ⭐ | 玩家反复做的"动作→反馈→奖励"循环。游戏好不好玩全看它 |
| **垂直切片（Vertical Slice）** ⭐ | 一小段但"完整"的成品——包含最终品质的美术、音效、UI。用来验证方向 |
| **Game Feel / 手感** ⭐ | 操作起来的反馈质量（跳跃的爽快、打击的重量感）。**小游戏靠这个赢** |
| **Coyote Time（土狼时间）** | 离开平台后仍允许短暂跳跃，减少"不跟手"感 |
| **Jump Buffer（跳跃缓冲）** | 落地前提前按跳，落地瞬间自动执行 |
| **无敌帧（i-frames）** | 受伤后短暂的无敌时间，防止被连续扣血 |
| **状态机（State Machine）** | 用"状态"管理角色行为（IDLE/RUN/JUMP/FALL），避免 if-else 爆炸 |
| **碰撞检测** | 判断两个物体是否接触 |
| **Hitbox / Hurtbox** | 攻击判定区 / 受击判定区 |
| **关卡设计（Level Design）** | 用空间和节奏引导玩家的手艺。**新手的试金石** |
| **Prototype（原型）** ⭐ | 用最粗糙的形式验证玩法（纸片、色块），别急着做美术 |
| **Scope（范围）** ⭐ | 项目要做多少东西。**新手失败的第一原因就是 Scope 太大** |
| **Polish（打磨）** | 加音效、粒子、屏幕震动、缓动曲线等"让它像个产品"的工作 |
| **GDD（游戏设计文档）** | 一页纸写清游戏是什么、怎么做、不做什么 |
| **Postmortem（复盘）** | 项目结束后写的"做了什么、错在哪"的总结 |
| **itch.io** ⭐ | 独立游戏发布平台，免费上传，最适合第一次发布 |
| **Steam** | 主流 PC 游戏平台。**第一次发布不要去**（要 $100 上架费、要过审、要做商店页打磨） |

## 六、素材与法律（发布前必须搞清）

| 术语 | 一句话解释 |
|---|---|
| **CC0 / 公有领域** ✅ | 最宽松：可商用、可改、**无需署名**。Kenney.nl 就是全 CC0 |
| **CC-BY** | 可商用、可改，**必须署名**（要在游戏里或说明里写作者名） |
| **CC-BY-SA** | 同上，但**衍生作品必须用同样许可**（"传染性"，可能要求你开放自己的作品，谨慎！） |
| **CC-BY-NC** ⚠️ | **NC = Non-Commercial，不能商用**。做商业游戏绝对不能用 |
| **Royalty-free** | 免版税，但**不等于免费**，也不等于可以随便用，要看具体条款 |
| **Attribution（署名）** | 注明原作者。很多免费素材要求这个，忘记署名是常见违规 |
| **Commercial Use（商用）** | 用来赚钱。判断标准不只是"我收钱了"，投放广告、众筹也算 |
| **Public Domain** | 版权已过期或放弃，任何人都可用 |

> **每次使用素材的固定动作**：找到 License 原文 → 用 `[P-37]` 让它解读 → 三个问题（能商用吗/要署名吗/能改吗）写进 `godot笔记/05-素材许可.md`。
> **有一个答不上来就换素材。** 做完游戏不敢发布，通常就是卡在这一步。

## 七、遇到不认识的词怎么办（通用流程）

1. 先问 AI：用 `[P-01]` 模板，要求"生活比喻 + 不懂会踩什么坑 + 一个最小验证动作"
2. **如果它给的是版本号、价格、平台政策 → 必须去官网核实**，不要相信 AI 的转述（这类信息 AI 极易编造或过时）
3. 记进 `学习日志.md`，标注日期（政策类信息要标日期，因为会变）
4. 如果一个词你查了三次还是不懂 → 说明缺的是它下面一层的前置知识，去补那个
