# 12 周每日任务表（84 天）

**怎么用这份表**：每天找到对应的一天，按"▶ 步骤"做，产出"✅ 交付物"。提示词编号（如 `[P-03]`）指向 `03-AI协作提示词库.md`。
**每日时段**：① 运行 10 分钟 → ② 造 60 分钟 → ③ 讲 20 分钟。
**周日**：只做复盘（30 分钟），填 `00-总纲` 第 7 节的复盘表。
**落后了怎么办**：周末补，但**绝不允许跳过"运行"**。

# 第 1 周 ｜ 奠基：环境 + GitHub + 多模型矩阵

🎯 本周结束你会：有一个 GitHub 仓库、会用 3 个模型对比同一个问题、能说出"什么任务派哪个模型"。

### Day 01 ｜ 装 Git + 注册 GitHub ｜ 120 分钟
🎯 目标：本机有 git 命令；GitHub 上有你自己的第一个仓库。
📦 需要：`05-环境搭建清单.md` 的 A 节。
▶ 步骤：
1. 装 Git for Windows（全默认）→ **重启电脑**
2. PowerShell 输入 `git --version`，看到版本号
3. 注册 GitHub → 邮箱验证
4. 装 GitHub Desktop，登录
5. 运行 A4 的四条 `git config` 命令
6. 网页上新建仓库 `ai-game-learning`（Public + README）
7. GitHub Desktop 克隆到 `D:\dev\ai-game-learning`
🤖 让 AI 干什么：`[P-01]` 让它用"给非计算机专业的人"的方式解释 Git 和 GitHub 的区别。
✅ 交付物：`git --version` 输出截图 + GitHub 上有 `ai-game-learning` 仓库 + 本地已克隆。
❗ 常见坑：装完不重启；用户名用中文；仓库名用中文。

### Day 02 ｜ 建多模型矩阵 ｜ 90 分钟
🎯 目标：3 个模型的账号都能用，完成第一次"三模型对比"。
▶ 步骤：
1. 确认可用：ChatGPT、Claude、DeepSeek（哪个没有就去注册哪个）
2. 用同一个问题分别问三个模型：
   > "我要从零学做游戏，不会编程，Godot 和 Unity 该选哪个？用 200 字回答，给我三个理由和一个反对意见。"
3. 把三段回答并排贴进 `学习日志.md`
4. 写 3 行结论：谁的答案最具体？谁最啰嗦？谁给的行动建议最可执行？
5. 再问一次 Claude 和 GPT：`[P-01]` 编号里的"术语解释模板"
🤖 让 AI 干什么：这一天的任务**本身就是**用 AI。
✅ 交付物：`学习日志.md` 里有三段回答 + 你的 3 行结论。
❗ 常见坑：只问一个问题就下结论。**至少比 3 个问题**（概念类、代码类、创意类各一个）才知道差异。

### Day 03 ｜ 模型分级与选型 ｜ 90 分钟
🎯 目标：建立"分级用模型"的判断力（这是"多模型运用"的核心）。

1. 打开三家官网的 Models / Pricing 页面，看**当前实际存在的模型**和价格
2. 在 `学习日志.md` 建一张表：模型名 / 价格档位 / 你打算用它做什么
3. 造三类任务，各派一个模型，验证你的判断：
   - 任务A（要便宜量大的日常）：把一段中文游戏介绍翻译成英文
   - 任务B（要最强推理）：给你一段故意写错的代码，让它找 bug
   - 任务C（要长文档理解）：把 `00-总纲` 全文贴给它，让它总结成 5 条
4. 记录哪个模型在哪个任务上明显更好/更差
🤖 让 AI 干什么：`[P-02]` 让它给你设计"同一问题的三档问法"。
✅ 交付物：模型分级表 + 三类任务的结果对比。
❗ 常见坑：**不要记版本号**（网上大量版本名是假的或代号），要记"什么任务派谁"。

# 第 2 周 ｜ GitHub 实战 + Godot 安装与跑通别人的项目

🎯 本周结束你会：从 GitHub 下载完整项目 → 用 Godot 打开 → 运行成功 → 改掉一个数值。

### Day 08 ｜ 装 Godot 并跑起官方模板 ｜ 120 分钟
🎯 目标：Godot 装好，跑通官方 demo。
📦 需要：`05-环境搭建清单.md` 的 C 节。
▶ 步骤：
1. 下载 Godot 4.x **标准版** zip，解压到 `D:\dev\Godot\`，建桌面快捷方式
2. 打开 → 界面语言设为简体中文 → 重启
3. `AssetLib` 搜索 `Dodge the Creeps` 或 `2D Platformer` → 下载 → 打开
4. 按 `F5` 运行，玩一遍
🤖 让 AI 干什么：`[P-08]` 让它解释"项目（Project）/ 场景（Scene）/ 节点（Node）"的关系。
✅ 交付物：Godot 能运行，玩了官方 demo，截图存日志。
❗ 常见坑：下了 .NET 版本；解压到中文路径。

### Day 09 ｜ 学会自己建项目 + 场景树 ｜ 90 分钟
🎯 目标：明白"场景 = 一棵节点树"。
▶ 步骤：
1. `新建项目` → 路径 `D:\dev\playground\first-project`
2. 右侧 `场景` 面板 → `其他节点` → 搜 `Node2D` → 创建
3. 右键这个 Node2D → `添加子节点` → 加 `Sprite2D` → 再加 `Camera2D`
4. 观察左侧场景树：**缩进就是父子关系**。拖动节点改变父子关系，看坐标变化
5. 在 `检查器` 面板改 Sprite2D 的 `位置`，看画面变化
6. 保存场景为 `main.tscn`
🤖 让 AI 干什么：`[P-09]` 让它用"文件夹套文件夹"比喻解释节点树。
✅ 交付物：`first-project` 项目能打开，有一个 3 层节点树的场景。
❗ 常见坑：以为节点是"组件"贴在对象上。**节点就是对象本身，树是它们的组织方式**。

### Day 10 ｜ 第一个脚本：让方块动起来 ｜ 90 分钟
🎯 目标：第一次写代码，理解"脚本挂在节点上"。
▶ 步骤：
1. 选中 Node2D → 右侧 `附加脚本` → 路径 `res://player.gd` → 创建
2. 让 AI 写：`[P-10]` "写一个 Godot 4 的 GDScript，让节点每秒向右移动 100 像素，并在窗口边缘回到左边"
3. 把代码粘进 `player.gd`，按 F5 运行
4. 改数字：100 → 300，再跑一次，看差异
5. 故意删掉一个 `:` 或把 `_process` 拼错，看报错长什么样
🤖 让 AI 干什么：`[P-10]` 生成代码 + `[P-11]` 逐行讲解。
✅ 交付物：一个会移动的方块 + 日志里"我看懂的那 5 行"。
❗ 常见坑：以为 `_process(delta)` 里的 `delta` 是"帧数"。**它是上一帧到这一帧的秒数**，乘上它才能在不同电脑上速度一致。

### Day 11 ｜ 从 GitHub 下载一个完整项目 ｜ 120 分钟
🎯 目标：学会"找项目 → 下载 → 跑起来"这套流程。
📦 需要：`02-GitHub学习项目库.md` 的 #1 或 #2。
▶ 步骤：
1. 打开目标仓库，先读 `README.md`（重点看：需要什么 Godot 版本）
2. 点绿色 `Code` → `Download ZIP`
3. 解压到 `D:\dev\godot-demos\<项目名>`
4. 用 Godot 的 `导入` 功能打开它（选 `project.godot` 所在的文件夹）
5. 按 F5 运行。**如果报错，把报错原文整段复制给 AI**，问"这个项目缺什么、怎么修"
6. 记录：这个项目有几个场景？入口场景是哪个？
🤖 让 AI 干什么：`[P-12]` 把报错贴给它，让它给你**一步步**的修复方案（不是一次给全部）。
✅ 交付物：这个项目在你电脑上跑起来了，日志里有它的结构说明（3～5 行）。
❗ 常见坑：项目是 Godot 3 写的，用 Godot 4 打开会大量报错。**看 README 的版本要求，必要时去下对应版本**。

### Day 12 ｜ 读懂一个项目：入口与主脚本 ｜ 120 分钟
🎯 目标：掌握"读别人项目"的固定路线。
▶ 步骤（固定路线，以后每天都用）：
1. 看 `project.godot` 里指定的**主场景**是哪个（或在 项目设置 → 应用 → 运行 里看）
2. 打开主场景，看场景树有哪几层
3. 找**挂着脚本的节点**（节点名旁边有小卷轴图标）
4. 打开主脚本，只看三个东西：`_ready()`（开始时做什么）、`_process()`（每帧做什么）、`_input()`（按键做什么）
5. 用 `[P-13]` 让 AI 用"导游式"讲解这个脚本，但**要求它先不讲细节，只讲整体流程**
🤖 让 AI 干什么：`[P-13]` 项目导读。
✅ 交付物：日志里写出这个项目的"执行流程图"，5 行以内。
❗ 常见坑：一上来逐行读所有代码 → 10 分钟就放弃。**先看流程，再看细节**。

### Day 13 ｜ 修改别人的项目（最快的学法）｜ 90 分钟
🎯 目标：体验"改动 → 观察 → 理解"的循环。
▶ 步骤：在 Day11 的项目里做 5 个改动，每改一个**立刻跑一次**：
1. 把玩家移动速度改成 3 倍
2. 把敌人/障碍的数量改成 20 个
3. 把背景颜色改成紫色
4. 把某个音效音量调到 0
5. 把分数增加的数值从 1 改成 100
6. 每个改动在日志里写一行"我改了哪个文件的哪一行"
🤖 让 AI 干什么：`[P-14]` 问它"我想改 X，应该在哪个文件找什么关键词"（**教它教你怎么找，而不是直接给你答案**）。
✅ 交付物：日志里有 5 行改动记录 + 改后的截图。
❗ 常见坑：改完不跑就继续改。**一次只改一处**。

### Day 14 ｜ 周整合：把本周成果沉淀 ｜ 120 分钟
▶ 步骤：

# 第 3 周 ｜ Godot 核心：节点、场景、信号、输入

🎯 本周结束你会：从零做一个能操控的角色（走、跳、撞墙）。

### Day 15 ｜ 2D 物理节点选型 ｜ 90 分钟
🎯 目标：搞懂 CharacterBody2D / Area2D / StaticBody2D 分别干什么。
▶ 步骤：
1. 新建项目 `D:\dev\playground\platformer`
2. 建场景：`Node2D`（名字 `Level`）→ 子节点 `CharacterBody2D`（名字 `Player`）→ 它的子节点 `CollisionShape2D` + `Sprite2D`
3. 给 CollisionShape2D 设形状为矩形，调整大小到和 Sprite 差不多
4. 再加一个 `StaticBody2D`（名字 `Ground`），同样加 CollisionShape2D 和 Sprite2D，拉长当平台
5. 用 `[P-15]` 让 AI 讲清三种物理体："谁会被撞飞、谁撞不动、谁只是感应区"
🤖 让 AI 干什么：`[P-15]` 概念对比表。
✅ 交付物：有 Player 和 Ground 的场景，能保存运行（角色还没动）。
❗ 常见坑：忘了给 CollisionShape2D 设形状 → 碰撞完全不起作用。**形状是必须的**。

### Day 16 ｜ 玩家左右移动 + 重力 ｜ 120 分钟
🎯 目标：第一次写出有物理感的移动。
▶ 步骤：
1. 给 Player 附加脚本 `player.gd`
2. 用 `[P-16]` 让 AI 写"Godot 4 的 CharacterBody2D 左右移动 + 重力 + 落到地面停住"的完整代码，**要求带中文注释**
3. 粘贴 → 运行 → 用方向键测试
4. 调参实验（每个都跑一次）：重力 980→500、速度 300→800、加速度改成瞬间到最大
5. 日志记录：哪个参数改变了什么手感
🤖 让 AI 干什么：`[P-16]` 生成 + `[P-11]` 逐行讲解。
✅ 交付物：能用方向键左右走、会掉下来停在地上的角色。
❗ 常见坑：`move_and_slide()` 后忘了处理 `velocity`；把 `delta` 漏乘导致速度随帧率变化。

### Day 17 ｜ 跳跃（含"土狼时间"）｜ 120 分钟
🎯 目标：理解游戏手感的第一个专业概念。
▶ 步骤：
1. 用 `[P-17]` 让 AI 加跳跃，且要求：只有在地上才能跳、松开按键跳得矮
2. 运行测试：能否连跳？能不能在空中跳？（应该是不能）
3. 用 `[P-18]` 让 AI 加 **土狼时间（Coyote Time）** 和 **跳跃缓冲（Jump Buffer）**，并解释这两个词
4. 亲自体验：加了之后手感有什么不同？写进日志
🤖 让 AI 干什么：`[P-17]` `[P-18]`。
✅ 交付物：手感舒服的跳跃，日志里有"土狼时间的定义 + 我体感到的差别"。
❗ 常见坑：`is_on_floor()` 必须放在 `move_and_slide()` **之后**判断才准。

### Day 18 ｜ 输入系统与键位配置 ｜ 90 分钟
🎯 目标：不写死按键，用 Godot 的输入映射。
▶ 步骤：
1. `项目 → 项目设置 → 输入映射` → 添加动作 `move_left` / `move_right` / `jump`
2. 给每个动作绑定键盘键（→ ← 空格）
3. 改代码：把 `Input.is_key_pressed(KEY_LEFT)` 换成 `Input.is_action_pressed("move_left")`
4. 再给 `jump` 额外绑定手柄按钮，运行测试
5. 用 `[P-19]` 让 AI 解释"为什么不该写死按键"
🤖 让 AI 干什么：`[P-19]`。
✅ 交付物：输入映射里有 3 个动作，代码用动作名而非键码。
❗ 常见坑：动作名拼错 → 运行时报错说找不到 action。

### Day 19 ｜ 信号（Signal）：节点之间怎么说话 ｜ 120 分钟
🎯 目标：理解 Godot 最核心的解耦机制。
▶ 步骤：
1. 做一个 `Coin` 场景：`Area2D` + `CollisionShape2D` + `Sprite2D`
2. 在 Coin 上附加脚本，用 `[P-20]` 让 AI 写"玩家进入 Area2D 时发出一个 collected 信号，然后自己消失"
3. 给 Player 加 `body_entered` 信号连接（在编辑器里用"节点 → 信号"面板连接，**不要全靠代码**）
4. 在连接函数里 `print("吃到金币")`，运行验证
5. 用 `[P-21]` 让 AI 讲"信号 vs 直接调用函数"的区别
