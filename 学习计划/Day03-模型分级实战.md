## 第 2 步：任务 A —— 便宜档的活（15 分钟）

### 做法

复制下面原文和提示词，**派给你分级表里最便宜的档**（免费档 / Flash / Luna 这类）。

**原文（照抄，不要改）：**

```
《星轨拾荒者》是一款 2D 像素风 roguelike 小游戏。你扮演一名在废弃空间站之间穿梭的拾荒者：每局地图随机生成，收集零件、升级飞船、对抗失控的安保机器人。游戏强调"短局体验"——一局 10 分钟，死了就重开，但每次都能带走一点永久强化的资源。适合喜欢《以撒的结合》和《挺进地牢》的玩家。
```

**提示词（照抄）：**

```
把下面这段中文游戏介绍翻译成英文，用于 Steam 商店页简介。
要求：1) 保留"短局、随机、永久强化"的产品卖点；2) 游戏名《星轨拾荒者》译作 Starfall Scavenger；
3) 只输出英文，不要解释、不要加标题。
【把上面的原文粘在这里】
```

### 判分标准（对着这几条打分，别只看"读起来顺不顺"）

| 检查点 | 合格表现 | 典型翻车 |
|---|---|---|
| **"局"** | `run`（roguelike 圈的固定词） | 译成 `game` / `round` —— 圈子内行一眼看出是外行 |
| **"永久强化"** | `permanent upgrades` / `meta-progression` | 丢掉这层意思（这是 roguelike 的核心卖点） |
| **roguelike / 像素风** | `roguelike` 保持原词不译；`pixel art` / `2D pixel-art` | 把 roguelike 意译成"随机地牢游戏" |
| **两个游戏名** | 官方英文名：**The Binding of Isaac**、**Enter the Gungeon** | 直译成《以撒的结合》的字面意思（外国人搜不到） |
| **有没有加戏** | 不加没说的内容 | 自己加"史诗级""业界领先"这种营销词 |

> 💡 **任务 A 的隐藏考点**：机械任务里也藏着**两个专有名词**（两个游戏名）。**便宜档在这里翻不翻车，决定它能不能当你的默认档。**
> 如果翻车了：不是"免费档没用"，而是**这类含专有名词的任务要加一句约束**（把固定译名写进提示词）。**这就是"用对档位"之外的第二个技能：把约束写清楚。**

## 第 3 步：任务 B —— 主力/旗舰档的活（30 分钟）

### 为什么任务 B 是整周最好的试金石

因为它**有标准答案**（`Day03-TaskB-标准答案.md`）。
"答案好不好"很主观，但"**有没有找全错误**"是客观的、可打分的。
**这是你第一次能真正量化地比较模型**，而不是凭感觉说"××好像聪明一点"。

### 做法

1. 打开 `Day03-TaskB-错误代码.md`，复制里面那段代码（**20 行，有 5 处问题 + 1 处干扰项**）
2. 用下面的提示词，**分别**派给两个不同档位（建议：免费档一次 + Terra/旗舰一次）
3. 两边的回答都存下来，对着标准答案数"找全了几个"

**提示词（照抄，注意第 3 条很重要）：**

```
下面是一段 Godot 4 的 GDScript 代码，里面有若干处错误，它现在跑不起来。
请按这个格式逐条列出问题：
1) 【会报错的】：哪一行、什么错、怎么改
2) 【不报错但行为不对的】：哪一行、为什么不对、怎么改
3) 【看起来可疑但其实是对的】：如果有，也请指出并说明为什么对
不要重写整份代码，只列问题。最后给一句总评：这段代码的主要问题是什么。
【把代码粘在这里】
```

> ⚠️ **提示词里第 3 条是"钓"幻觉的**：一段坏代码里塞一个**故意设的正确写法**。
> 只会顺着找茬的模型，会把这个正确写法也"修"坏——**这种模型不能信**。能找到并说清"为什么它对"的，才是真读懂了。

### 判分（满分 5 分 + 1 分附加）

| 出现的问题 | 分值 | 说明 |
|---|---|---|
| 找到 **3 个会报错的硬错误** | 3 分（每个 1 分） | 这是底线。硬错误都找不出来 = 这档不能用于改代码 |
| 找到 **2 个逻辑错误** | 2 分（每个 1 分） | 分开档次的关键：能跑 ≠ 正确 |
| 指出那处**干扰项其实是正确的**并说明原因 | +1 分 | 附加分，最能说明"真的懂" |

**记录格式**（填进 `Day03-三任务对比记录.md`）：

```
免费档：找到 __/5，附加分 __，把干扰项误判了吗：是/否
Terra/旗舰：找到 __/5，附加分 __，把干扰项误判了吗：是/否
```

> 💡 **这一题真正的收获**：你会看到**"便宜的模型不是不行，而是错的方式不一样"**——它可能只报 1 个错、或者把正确的改坏。
> **能跑起来的坏代码比报错的代码更危险**，因为没人提醒你。所以：**越是要动真实项目，越要往上提档位。**

## 第 4 步：任务 C —— 长文档 + 便宜的活（20 分钟）

### 做法

把 `00-总纲-学习路线图.md` **全文**粘给一个模型，让它压成 5 条。

**提示词（照抄）：**

```
下面是一份 12 周学习计划的全文。请压缩成 5 条，每条不超过 40 字，
要求覆盖：要纠正的认知、阶段划分、每日节奏、验收标准、最容易放弃的地方。
只输出 5 条，不要展开、不要鼓励我。
【把 00-总纲 全文粘在这里】
```

### 判分标准（这 5 条是"必含点"，缺一条就是漏信息）

| 必含点 | 总纲里的出处 |
|---|---|
| ① **路线是反的**：先让 AI 写能跑的代码，再回头读懂（不是先学语法） | 第 0 节 认知一 |
| ② **必须读懂代码**，不能只复制粘贴 | 第 0 节 认知二 |
| ③ **只学 GDScript（+一点 JS）**，不要碰 Python / C++ | 第 0 节 认知三 |
| ④ **四阶段 + 验收标准**（P0 奠基 → P3 发布到 itch.io，有真人玩 5 分钟） | 第 1 节 |
| ⑤ **每天必须运行、卡住 40 分钟就跳过**（"死磕是放弃的前兆"） | 第 1 节 + 日志提醒 |

> ⚠️ **任务 C 的成本陷阱（今天最重要的一课）**：
> 1.4 万字的文档，**如果派给最贵的旗舰档（Astra 6.67x），你会花 6.67 倍的钱去干一件"压缩"的活**。
> **长文档任务的正确选型是"上下文便宜"的档**（长文本专用档 / 便宜档），不是"最聪明"的档。
> → **判断口诀：文档越长，越要压低"单价"，而不是提高"智商"。**
