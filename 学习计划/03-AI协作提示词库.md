# AI 协作提示词库（可直接复制使用）

> **用法**：把 `【】` 里的内容换成你的实际情况。用熟了就把改好的版本存进你自己的 `我的提示词本.md`。
> **最重要的 5 条**（时间不够就只用这 5 条）：`[P-12]` 报错诊断、`[P-13]` 代码导读、`[P-11]` 逐行讲解、`[P-03]` 费曼讲解、`[P-60]` 先方案后代码。

---

## 一、基础沟通类（第 1 周）

### [P-01] 术语解释模板
```
我是完全不懂编程的人，第一次接触这个领域。请解释【Git 和 GitHub 的区别】：
1. 先用一个生活比喻（不要用技术比喻）
2. 再用不超过 100 字说清它实际是干什么的
3. 告诉我：这个概念不懂会导致我后面踩什么坑
4. 最后给我一个"我现在就能做的最小验证动作"
不要用"仓库""提交""分支"这些词来解释它们自己。
```

### [P-02] 三档问法（同一问题不同深度）
```
关于【Godot 的信号机制】，请给我三个版本的回答：
- 30 秒版：只讲它解决什么问题
- 3 分钟版：加上一个最小代码例子
- 深入版：加上它和直接调用函数的区别、什么时候不该用
```

### [P-03] 费曼讲解（学任何新概念都用这条）
```
请当我的老师，用费曼学习法教我【什么是 API】：
1. 先假设我是初中生，用生活例子讲
2. 然后指出我刚才可能会误解的地方（列出 3 个常见误解）
3. 给我一个可以在电脑上 5 分钟做完的小实验来验证我懂了
4. 最后出 3 道题考我，等我回答后再给答案
```

### [P-04] 概念辨析（易混词）
```
请用一个表格对比这 4 个词：【commit / push / pull / branch】，
列：中文意思、生活比喻、"我什么时候会用到它"、不做它的后果。
表格后写一句话：初学者最容易搞混的是哪两个，为什么。
```

### [P-05] 结构审查
```
这是我的文件夹结构：【粘贴树状结构】。
我的目标是【学做 Godot 游戏，12 周后发布一款小游戏】。

3. 给出一个更好的结构，并说明每一层为什么这样分
不要客套，直接说问题。
```

### [P-06] 反问答（让 AI 考你）
```
我刚学了【节点、场景、脚本】。请出 5 道题考我，难度递进：
2 道概念题、2 道"这段代码在做什么"的读代码题、1 道动手题。
先只出题，不要给答案。等我回答后，逐题告诉我哪里错了、为什么错。
```

### [P-07] 严格审查员
```
请扮演一个非常严格的【技术项目审查员】。这是我要提交的【README.md 内容】。
请从"一个陌生人能否在 3 分钟内看懂并跑起来"的角度审查，列出所有问题，按严重程度排序。
每个问题给出修改后的原文（可直接替换）。
```

## 五、通用增效技巧（贴在显示器旁边）

| 技巧 | 具体做法 |
|---|---|
| **不许一次给全部** | 任何多步任务都加一句："一次只给一步，等我回复再继续" |
| **要它先问再答** | 任务描述不完整时加："如果信息不够，先问我问题，不要猜" |
| **要它标不确定** | 加："不确定的地方明确说不确定，不要编" |
| **要它教方法不要给答案** | 加："教我怎么找到答案，而不是直接给我答案" |
| **换任务就开新对话** | 同一个对话里混三件事，AI 会开始串味 |
| **关键改动先 commit** | 让 Agent 改文件前，先在 Git 里提交一次，出问题能一键回滚 |
| **要求它自检** | 代码类回答后加："检查你自己的答案有没有 Godot 4 语法错误，有就修正后重新给" |
